# User Personas

## Persona 1: System Administrator

**Name:** Sarah Chen

**Description:** A project manager or team lead responsible for coordinating architecture deliverables across the team. Manages the bulletin board to track work assignments and ensure deliverables are completed on time.

**Demographics:**
- Age range: 30-50
- Technical proficiency: High - comfortable with web applications and GitHub
- Role/Position: Project Manager, Team Lead, Delivery Manager

**Goals:**
- Post clear task requirements with all necessary context
- Assign work to appropriate architects based on expertise and availability
- Monitor progress of all active tasks
- Receive timely notifications when tasks need attention (escalations, closures)
- Maintain organized bulletin board by archiving completed work
- Ensure deliverables meet quality standards before closing tasks

**Pain Points:**
- Difficulty tracking who is working on what across multiple tasks
- Losing important artifacts or conversations in email threads
- No central place to view all active deliverables
- Hard to maintain accountability when tasks are spread across tools
- Challenging to search historical deliverables for reference

**User Needs:**
- Quick post creation with file attachments
- Clear visibility of all task statuses at a glance
- Ability to reassign tasks when priorities change
- Search and filter capabilities to find specific tasks
- Notification system for critical events (escalations, submissions)
- Archive and export functionality for compliance and reporting
- Control panel to manage team configuration

**Typical Workflow:**
1. Receives a request for architecture deliverable
2. Creates bulletin post with problem statement and context
3. Assigns one or more architects based on expertise
4. Monitors progress through status updates
5. Reviews submitted artifacts
6. Engages in chat thread if clarification needed
7. Approves and closes task when deliverable is satisfactory
8. Archives completed tasks periodically

## Persona 2: Solution Architect

**Name:** David Kumar

**Description:** A technical architect responsible for creating architecture deliverables, designs, and technical documentation. Works on assigned tasks and collaborates with admins through the bulletin board.

**Demographics:**
- Age range: 28-45
- Technical proficiency: Very High - strong GitHub and technical tool experience
- Role/Position: Solution Architect, Technical Architect, Enterprise Architect

**Goals:**
- Understand task requirements clearly
- Take ownership of tasks that match expertise
- Upload deliverable artifacts with proper versioning
- Communicate progress and blockers effectively
- Get clarification on requirements through threaded conversations
- Deliver high-quality architecture artifacts on time
- Maintain visibility of all team work (even unassigned tasks)

**Pain Points:**
- Unclear or incomplete requirements
- Difficulty finding supporting documents or context
- No version history when iterating on deliverables
- Lack of structured communication channel with task owners
- Hard to know which tasks need help (unassigned tasks)
- Cannot track conversation history for reference

**User Needs:**
- Clear view of all bulletin posts to understand team workload
- Ability to self-assign to available tasks
- Easy file upload with version tracking
- Threaded conversation capability for Q&A
- Text area to document thoughts and closure notes
- Visual distinction between assigned and unassigned tasks
- Search capability to find related historical deliverables
- Image preview for attached diagrams and screenshots

**Typical Workflow:**
1. Logs in and scans bulletin board for all posts
2. Reviews unassigned or newly assigned tasks
3. Self-assigns to tasks matching expertise (if allowed)
4. Asks clarifying questions via chat thread
5. Works on deliverable offline
6. Uploads artifact v1 with closure thoughts
7. Receives feedback from admin in thread
8. Uploads artifact v2 with revisions
9. Submits for review
10. Waits for admin approval and closure

## Persona 3: Team Viewer (Future Consideration)

**Name:** Lisa Thompson

**Description:** A stakeholder or team member who needs read-only access to view deliverables and progress but doesn't create or work on tasks.

**Demographics:**
- Age range: 30-55
- Technical proficiency: Medium - can navigate web applications
- Role/Position: Stakeholder, Manager, Team Member

**Goals:**
- Monitor progress of architecture deliverables
- View completed artifacts for reference
- Understand team workload and capacity
- Search for historical deliverables

**Pain Points:**
- No visibility into ongoing architecture work
- Cannot track deliverable status
- Hard to find completed work for reuse

**User Needs:**
- Read-only access to bulletin board
- Search and filter capabilities
- View artifacts and conversations
- Export capabilities for reporting

**Note:** This persona is documented for future phases. Initial release focuses on Admin and Architect roles only.
